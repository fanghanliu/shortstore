# 账号体系与下载后业务流程规划

## 1. 文档目标

这份文档用于规划平台从“游客可下载免费前三集”升级到“可识别用户、可沉淀行为、可承接后续购买/按集/分成合作”的账号与业务流程。

它承接前一份文档：

```text
docs/download-access-and-user-identity-rules.md
```

前一份文档解决的是：

- 同一剧本是否允许多人下载。
- 下载后是否继续展示。
- 未注册用户如何记录下载行为。
- 为什么不建议下载前强制注册。

这份文档继续解决：

- 账号系统什么时候出现。
- 游客下载记录如何绑定到注册用户。
- 下载成功后应该引导用户做什么。
- 用户中心最小版本应该包含什么。
- 后续买断、按集、分成入口如何接上。
- 数据库和 API 应该如何扩展。

## 2. 核心判断

当前平台不应该把“注册登录”设计成免费预览包下载前的门槛。

更合理的路径是：

```text
先让用户看到价值，再引导用户留下身份。
```

也就是：

```text
浏览剧本库
进入剧本详情
确认授权边界
下载前三集验证包
下载成功后引导注册
注册后绑定游客下载记录
进入用户中心
提交测试反馈或申请后续合作
```

原因是：

- 免费前三集是信任入口，不是收费墙。
- 早期平台更需要降低首次体验门槛。
- 下载前强制注册会削弱“专业内容平台”的感受。
- 下载后用户已经获得内容，注册动机更自然。
- 后续购买、按集、分成才是真正需要账号身份的环节。

## 3. 整体用户路径

### 3.1 未登录用户路径

```text
首页
  ↓
剧本库
  ↓
剧本详情页
  ↓
点击下载免费前三集
  ↓
勾选授权确认
  ↓
生成游客 visitorId
  ↓
记录 Download
  ↓
开始下载 Markdown 文件
  ↓
弹出下载后引导
  ↓
注册/登录 或 暂时跳过
```

这个路径的重点是：不阻断下载，但完整记录行为。

### 3.2 注册后用户路径

```text
注册/登录
  ↓
读取浏览器 visitorId
  ↓
绑定最近游客下载记录
  ↓
进入用户中心
  ↓
查看我的下载
  ↓
提交前三集测试数据
  ↓
选择后续方式
  ↓
买断 / 按集购买 / 分成申请
```

这个路径的重点是：把一次下载行为转成可继续经营的用户关系。

### 3.3 老用户路径

```text
登录状态访问
  ↓
浏览剧本库
  ↓
下载新剧本免费包
  ↓
Download 直接关联 userId
  ↓
用户中心自动出现下载记录
  ↓
后续合作入口可直接操作
```

老用户不需要重复身份确认，但每次下载仍然需要确认授权边界。

## 4. 注册登录出现的位置

### 4.1 不建议出现的位置

暂时不建议在以下位置强制注册：

- 进入首页前。
- 浏览剧本库前。
- 查看剧本详情前。
- 下载免费前三集前。

这些位置强制注册，会让用户在还没有理解产品价值前就承担成本。

### 4.2 建议出现的位置

建议在以下位置引导或强制登录：

| 场景 | 登录要求 | 说明 |
| --- | --- | --- |
| 免费前三集下载成功后 | 引导登录 | 不强制，但强提示 |
| 查看我的下载记录 | 必须登录 | 需要用户身份 |
| 提交测试数据 | 必须登录 | 数据要归属用户 |
| 收藏剧本 | 必须登录 | 收藏是个人资产 |
| 申请后续剧集 | 必须登录 | 涉及交易意向 |
| 申请版权分成 | 必须登录 | 涉及合作主体 |
| 买断完整剧本 | 必须登录 | 涉及订单和授权 |
| 按集购买 | 必须登录 | 涉及订单和交付 |

### 4.3 登录策略总结

```text
看内容：不登录
拿免费包：不强制登录
保存记录：登录
提交数据：登录
继续交易：登录
合作分成：登录
```

## 5. 下载后弹窗设计

### 5.1 弹窗出现时机

下载接口成功返回后，前端应立即：

1. 触发文件下载。
2. 写入本地 visitorId。
3. 展示下载后弹窗。

弹窗不是“下载确认弹窗”，而是“下一步行动弹窗”。

### 5.2 弹窗目标

下载后弹窗要完成三件事：

- 告诉用户文件已经开始下载。
- 提醒用户免费包的授权边界。
- 引导用户进入后续业务动作。

### 5.3 弹窗文案建议

标题：

```text
前三集验证包已开始下载
```

正文：

```text
你可以先用前三集制作测试视频，验证题材、开头钩子、剪辑节奏和账号受众匹配度。

如果后续需要继续制作第4集及以后的内容，可以注册账号保存下载记录，并选择买断、按集购买或版权分成合作。
```

授权提醒：

```text
免费验证包仅包含前三集内容，可用于测试制作与数据验证。第4集及后续内容、完整剧本、独占授权和分成合作，需要通过平台另行确认。
```

### 5.4 弹窗按钮

建议按钮优先级：

| 按钮 | 类型 | 行为 |
| --- | --- | --- |
| 注册并保存记录 | 主按钮 | 跳转注册页 |
| 登录账号 | 次按钮 | 跳转登录页 |
| 查看后续合作方式 | 次按钮 | 滚动到详情页续作模块或打开合作弹窗 |
| 稍后再说 | 文本按钮 | 关闭弹窗 |

不要在弹窗里塞太多内容。弹窗只负责把用户推向下一步。

## 6. 游客身份 visitorId

### 6.1 visitorId 的作用

`visitorId` 是浏览器本地生成的匿名访客 ID。

它用于在未登录时识别同一个浏览器的行为，例如：

- 下载过哪些剧本。
- 是否重复下载同一资源。
- 是否从下载后弹窗注册。
- 注册后能否绑定历史下载。

它不是用户真实身份，也不能替代登录账号。

### 6.2 生成规则

前端第一次访问时，如果本地没有 `visitorId`，则生成一个。

建议格式：

```text
visitor_随机字符串_时间戳
```

例如：

```text
visitor_lx92m4kq_20260528113022
```

保存位置：

```text
localStorage.scriptMarketVisitorId
```

### 6.3 使用规则

下载免费包时，前端必须把 `visitorId` 传给：

```text
POST /api/downloads
```

后端记录到 `Download.visitorId`。

如果用户已登录，则同时记录：

```text
Download.userId
```

如果用户未登录，则：

```text
Download.userId = null
```

### 6.4 风险边界

`visitorId` 有局限：

- 用户清理浏览器数据后会丢失。
- 换设备后无法自动识别。
- 不能证明用户真实身份。
- 不能作为付款、授权、分成依据。

所以它只用于游客行为衔接，不用于正式商业授权。

## 7. 注册后绑定游客记录

### 7.1 绑定时机

以下动作发生后，应尝试绑定游客记录：

- 注册成功。
- 登录成功。
- 用户中心首次打开。

推荐第一阶段在注册/登录成功后立即调用绑定接口。

### 7.2 绑定逻辑

```text
读取当前浏览器 visitorId
  ↓
调用 POST /api/me/bind-visitor-downloads
  ↓
后端查找 userId 为空且 visitorId 相同的 Download
  ↓
把这些 Download 的 userId 更新为当前用户 id
  ↓
返回绑定数量
```

### 7.3 绑定限制

为了避免误绑定，建议加入限制：

- 只绑定当前浏览器提供的 `visitorId`。
- 只绑定最近 30 天内的下载记录。
- 已有 `userId` 的记录不再覆盖。
- 一次绑定完成后记录绑定时间。
- 后端必须基于登录态识别当前用户，不能让前端传入任意 userId。

### 7.4 用户提示

绑定成功后，可以提示：

```text
已为你同步最近的下载记录。
```

如果没有可绑定记录：

```text
暂无可同步的游客下载记录。
```

## 8. 用户中心 MVP

### 8.1 用户中心目标

用户中心不是一开始就做成复杂后台。

第一版只需要承接下载后的关键动作：

- 查看下载过的剧本。
- 回到剧本详情页。
- 提交测试反馈。
- 选择后续合作方式。
- 查看自己的申请状态。

### 8.2 页面建议

建议新增：

```text
/account.html
```

如果后续迁移到正式路由，可以变成：

```text
/account
```

### 8.3 第一版模块

用户中心第一版建议包含四个模块：

| 模块 | 作用 |
| --- | --- |
| 我的下载 | 展示下载过的免费验证包 |
| 测试反馈 | 提交前三集测试视频数据 |
| 后续合作 | 申请买断、按集、分成 |
| 账号资料 | 显示昵称、邮箱、联系方式 |

### 8.4 我的下载

展示字段：

| 字段 | 说明 |
| --- | --- |
| 剧本标题 | 例如《她闻到谎言》 |
| 下载文件 | 免费前三集验证包 |
| 下载时间 | createdAt |
| 授权状态 | 免费测试授权 |
| 后续入口 | 继续购买 / 提交反馈 / 查看详情 |

### 8.5 测试反馈

第一版测试反馈只收核心数据：

| 字段 | 说明 |

| viewCount | 播放量 |
| likeCount | 点赞量 |
| commentCount | 评论量 |
| followerDelta | 涨粉量 |
| publishTime | 发布时间 |

这些数据未来可以帮助判断哪套剧本值得继续生产、投流或开放分成。

## 9. 后续合作入口

### 9.1 三种后续方式

下载前三集后，用户可以选择：

```text
一次性买断
按集购买
版权分成
```

这三种方式不应该混在一个“联系客服”按钮里，而应该作为明确的业务选项出现。

### 9.2 一次性买断

适合用户：

- 已经验证前三集数据不错。
- 想快速拿到完整内容。
- 想稳定持续更新。
- 有团队制作能力。

入口文案：

```text
申请买断完整剧本
```

需要登录。

第一版不一定直接在线支付，可以先创建意向记录。

### 9.3 按集购买

适合用户：

- 担心后续数据波动。
- 只想先拿第4-10集继续测试。
- 预算较低。
- 希望走一步看一步。

入口文案：

```text
申请按集继续购买
```

需要登录。

第一版可让用户选择：

```text
第4-10集
第4-20集
自定义集数
```

### 9.4 版权分成

适合用户：

- 不想前期付款。
- 愿意提供视频数据。
- 有账号、剪辑、投放或运营能力。
- 能接受平台按收益比例分成。

入口文案：

```text
申请分成合作
```

必须登录。

分成申请需要比买断和按集收集更多信息：

- 账号主页链接。
- 过往短剧数据。
- 预计发布平台。
- 更新频率。
- 团队能力。
- 收益结算方式。

## 10. 账号系统 MVP

### 10.1 第一版账号方式

第一版建议使用：

```text
邮箱 + 密码
```

暂时不做：

- 手机验证码。
- 微信登录。
- 第三方 OAuth。
- 企业认证。
- 复杂权限系统。

原因是当前项目重点不是账号技术复杂度，而是业务闭环跑通。

### 10.2 注册字段

建议字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| email | 是 | 登录账号 |
| passwordHash | 是 | 密码哈希 |
| displayName | 否 | 展示昵称 |
| contactWechat | 否 | 微信联系 |
| contactPhone | 否 | 手机号 |
| role | 是 | user / admin |
| status | 是 | active / disabled |

### 10.3 登录态

第一版建议使用：

```text
HTTP-only Cookie + Session
```

或者：

```text
JWT + HTTP-only Cookie
```

不建议把 token 直接存到 localStorage，因为后续涉及订单和合作申请，安全边界要更稳。

### 10.4 密码安全

必须做到：

- 密码不能明文存储。
- 使用 bcrypt 或 argon2 做哈希。
- 登录失败返回统一错误。
- 后端不要返回 passwordHash。

## 14. 下载后的状态流转

### 14.1 免费下载完成

```text
Download.created
```

状态含义：

- 用户或游客已经下载。
- 仅获得前三集测试授权。
- 未产生后续交易。

### 14.2 注册绑定完成

```text
Download.boundToUser
```

状态含义：

- 下载记录已归属某个用户。
- 可以在用户中心展示。
- 可以作为提交测试反馈或申请后续的入口。

### 14.3 提交测试反馈

```text
TestReport.submitted
```

状态含义：

- 用户已经用前三集测试。
- 平台可以根据数据判断后续合作价值。

### 14.4 申请后续合作

```text
ContinuationRequest.submitted
```

状态含义：

- 用户有明确商业意向。
- 平台需要人工或后台处理。

## 15. 权限规则

### 15.1 游客可做

- 浏览首页。
- 浏览剧本库。
- 查看剧本详情。
- 下载免费前三集。

### 15.2 游客不可做

- 查看用户中心。
- 保存下载记录到账号。
- 提交测试反馈。
- 申请买断。
- 申请按集购买。
- 申请分成合作。

### 15.3 登录用户可做

- 查看我的下载。
- 提交测试反馈。
- 发起后续合作申请。
- 查看申请状态。
- 修改基础联系方式。

### 15.4 管理员后续可做

- 查看全部下载记录。
- 查看用户信息。
- 审核测试反馈。
- 处理后续合作申请。
- 修改剧本开放状态。
- 设置下载名额或独占锁定。

管理员后台不属于本阶段优先事项，但数据模型应预留。

## 16. 第一阶段实施范围

### 16.1 必做

账号体系 Phase 1 建议只做：

- 新增 User 表。
- 注册接口。
- 登录接口。
- 登出接口。
- 当前用户接口。
- 游客下载绑定接口。
- 用户下载记录接口。
- 注册/登录页面。
- 用户中心基础页。
- 下载成功后弹窗引导注册。

### 16.2 暂不做

第一阶段暂不做：

- 在线支付。
- 手机验证码。
- 微信登录。
- 邮箱验证。
- 找回密码。
- 管理员后台。
- 分成结算系统。
- 自动读取视频平台数据。
- 复杂权限角色。

### 16.3 原因

当前最关键的是跑通：

```text
免费下载 → 注册绑定 → 用户中心 → 后续申请
```

只要这条链路跑通，平台就从“内容展示网站”升级成“可运营的业务系统”。

## 17. 建议实施顺序

### Phase 1：账号基础

目标：

```text
用户可以注册、登录、退出、识别当前登录状态。
```

改动：

- Prisma 增加 User。
- 后端增加认证中间件。
- 前端增加 `auth.html`。
- 登录状态写入导航栏。

### Phase 2：游客下载绑定

目标：

```text
用户注册后，可以把注册前下载过的剧本同步到账号里。
```

改动：

- 前端统一生成 visitorId。
- 下载接口确保记录 visitorId。
- 新增绑定接口。
- 注册/登录成功后自动绑定。

### Phase 3：用户中心

目标：

```text
用户能看到自己的下载记录，并从记录进入下一步。
```

改动：

- 新增 `account.html`。
- 新增 `/api/me/downloads`。
- 下载记录卡片提供“查看详情”“提交反馈”“申请后续”。

### Phase 4：测试反馈

目标：

```text
用户能提交前三集测试视频数据。
```

改动：

- 新增 TestReport 表。
- 新增提交接口。
- 用户中心增加反馈表单。

### Phase 5：后续申请

目标：

```text
用户可以申请买断、按集购买或分成合作。
```

改动：

- 新增 ContinuationRequest 表。
- 分成合作可新增 RevenueShareApplication 表。
- 剧本详情页和用户中心提供申请入口。
