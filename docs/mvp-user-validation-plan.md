# MVP 用户验证计划

## 1. 当前阶段判断

截至目前，项目已经具备一个可以面对真实用户做小范围验证的 MVP。

这里的 MVP 不是正式商业化版本，也不是可以大规模公开投放的成熟产品。它的核心价值是：

让真实短视频创作者或内容团队体验完整流程，并验证“免费前三集剧本验证包 + 后续买断 / 按集 / 分成合作”这套商业模型是否有继续投入的价值。

当前最重要的问题不是“能不能马上赚钱”，而是：

- 用户是否理解这个产品。
- 用户是否愿意下载前三集。
- 用户是否愿意真的拿前三集去制作视频。
- 用户是否愿意回传测试数据。
- 用户是否会对后续买断、按集或版权分成产生兴趣。
- 用户是否信任这个网站和交付模式。
- 这个商业模型是否存在被认可、被使用、被转化的可能性。

所以本阶段目标应定义为：

验证商业前景，而不是追求收入最大化。

## 2. 验证目标

### 2.1 一级目标

验证“AI 短剧剧本售卖平台”是否存在真实用户需求。

具体来说，验证用户是否愿意把平台提供的剧本当成一个可以拿去测试、制作、运营和变现的内容资产，而不只是一个普通资料包。

### 2.2 二级目标

验证以下产品路径是否成立：

```text
用户浏览剧本
-> 下载前三集免费验证包
-> 用前三集制作测试视频
-> 回传播放和反馈数据
-> 根据结果申请后续合作
-> 平台审核并提供买断、按集或分成方案
```

如果这个路径被真实用户走通，说明项目具备继续投入的基础。

如果用户只浏览不下载，说明剧本展示、信任感或价值表达有问题。

如果用户下载但不制作，说明免费包价值、制作门槛或用户动机有问题。

如果用户制作但不申请后续，说明后续商业方式、剧本质量或转化节奏有问题。

## 3. 本次测试不以变现为核心

本阶段不要把收入作为唯一成功标准。

原因是项目此前一直处于封闭式开发，外界还没有接触过产品，也没有形成信任。用户第一次接触时，最重要的是观察他们是否愿意靠近产品、理解产品、尝试产品。

本阶段可以允许：

- 用户免费下载。
- 用户先体验，不立刻付款。
- 用户先提交意向，不强制交易。
- 分成合作先人工沟通，不做全自动开通。
- 付款先保留人工确认，不急着接支付系统。

但必须收集真实行为数据。

## 4. 核心验证假设

### 假设一：用户愿意用免费前三集降低试错成本

验证问题：

- 用户看到“前三集免费验证包”后，是否愿意下载？
- 用户是否觉得前三集足够判断一个剧本有没有潜力？
- 用户是否觉得免费包不是“骗联系方式”，而是一个真实可用的制作资产？

观察指标：

- 详情页访问量。
- 下载按钮点击率。
- 下载完成率。
- 下载后注册率。
- 用户对免费包内容完整度的评价。

### 假设二：用户愿意把剧本拿去真实制作

验证问题：

- 用户拿到前三集后，是否愿意实际制作视频？
- 他们卡在哪里：剧本理解、AI 画面提示词、剪辑、配音、发布，还是账号运营？
- 他们是否认为这套剧本足够支撑真实短视频测试？

观察指标：

- 下载后 3-7 天内是否提交测试反馈。
- 是否提交公开视频链接。
- 是否填写播放量、点赞、评论、涨粉等数据。
- 用户反馈中关于“制作难度”的描述。

### 假设三：用户愿意在验证后进入后续合作

验证问题：

- 用户测试后是否会申请买断、按集或版权分成？
- 哪一种方式最容易被接受？
- 用户对价格、授权、交付范围和分成规则是否理解？

观察指标：

- 测试反馈提交后，后续合作申请比例。
- 买断 / 按集 / 分成三种方式的选择分布。
- 用户在申请说明中主动提到的顾虑。
- 后台通过申请后，用户是否继续沟通。

### 假设四：版权分成是否具备早期吸引力

验证问题：

- 没有预算或不愿先付款的用户，是否愿意选择版权分成？
- 用户是否能接受按月回传视频和收益数据？
- 用户是否愿意签署线下或电子协议？

观察指标：

- 分成申请数量。
- 分成申请用户是否愿意提供账号、平台、发布计划。
- 分成项目开通后，用户是否按周期回传数据。
- 后台审核和结算沟通是否可执行。

## 5. 测试用户选择

本阶段不建议直接公开投放到大流量渠道。

建议先找 5-20 个真实但可沟通的测试用户。

优先选择：

- 正在做短视频账号的人。
- 做过 AI 视频、AI 漫剧、短剧混剪或小说推文的人。
- 有发布能力但缺剧本的人。
- 有内容团队但想降低试错成本的人。
- 对短剧变现、账号运营、带货或平台分账有兴趣的人。

暂时不优先选择：

- 完全没有短视频制作经验的人。
- 只想免费看资料但不愿测试的人。
- 无法提供任何反馈的人。
- 对 AI 短剧完全没有兴趣的人。

## 6. 测试入口设计

给测试用户的邀请话术不要像正式销售。

建议表达为：

```text
我们正在做一个 AI 短剧剧本验证平台。
现在不是正式售卖阶段，而是邀请少量创作者测试：
你可以免费领取剧本前三集，用来制作视频并发布测试。
如果测试数据不错，后续可以选择买断、按集购买或版权分成合作。
我们主要想验证这套模式是否真的能帮创作者降低选题和剧本试错成本。
```

不要强调：

- 保证爆火。
- 保证收益。
- 马上赚钱。
- 限时抢购。
- 独家内幕。

这些表达会损害信任。

应该强调：

- 免费前三集用于真实测试。
- 用户可以先验证再决定。
- 后续合作不是强制购买。
- 平台希望收集真实反馈。
- 项目还在 MVP 阶段，欢迎指出问题。

## 7. 用户测试路径

### Step 1：访问首页

观察用户是否能在 10 秒内理解：

- 这是一个短剧剧本平台。
- 可以先免费拿前三集。
- 后续有买断、按集和分成三种合作方式。

如果用户第一眼不知道网站做什么，说明首页文案和信息层级需要调整。

### Step 2：进入剧本库

观察用户是否会：

- 浏览多套剧本。
- 根据题材挑选。
- 点击详情页。
- 对某个剧本产生兴趣。

需要记录用户最先点击哪套剧本，以及为什么。

### Step 3：进入剧本详情

观察用户是否关心：

- 剧本卖点。
- 前三集内容。
- 适合平台。
- 制作难度。
- AI 提示词。
- 授权说明。

如果用户看完详情仍不知道下载后能拿到什么，说明详情页需要加强交付物展示。

### Step 4：下载前三集验证包

这是本阶段最关键的第一转化。

观察：

- 用户是否愿意下载。
- 下载前是否产生信任顾虑。
- 是否觉得必须注册很麻烦。
- 是否能理解免费包授权边界。

### Step 5：注册 / 登录

注册不是第一目标，但它是后续行为归属的基础。

观察：

- 下载后用户是否愿意注册。
- 用户是否理解注册的价值：保存下载记录、提交测试数据、申请后续合作。
- 注册流程是否有阻碍。

### Step 6：制作并发布前三集测试视频

这一环节不一定能当天完成。

建议给用户 3-7 天时间。

需要追踪：

- 用户是否开始制作。
- 是否卡在制作工具。
- 是否需要更详细的制作说明。
- 是否觉得提示词可用。
- 是否觉得剧本节奏适合短视频。

### Step 7：提交测试反馈

观察用户是否愿意填写：

- 视频链接。
- 播放量。
- 点赞量。
- 评论量。
- 涨粉量。
- 备注和主观判断。

如果用户不愿意回传，可能说明：

- 流程太麻烦。
- 用户没有真的制作。
- 用户不想暴露账号数据。
- 用户不知道回传后能获得什么。

### Step 8：申请后续合作

观察用户选择：

- 买断。
- 按集购买。
- 版权分成。

以及用户在申请说明里最关心什么：

- 价格。
- 是否独家。
- 能不能继续免费。
- 分成比例。
- 交付速度。
- 授权范围。
- 是否能商用。
- 是否能改编。

## 8. 关键指标

### 8.1 行为指标

| 指标 | 意义 |
| --- | --- |
| 首页访问人数 | 测试入口触达 |
| 剧本库访问人数 | 用户是否愿意挑选 |
| 详情页访问人数 | 剧本是否产生兴趣 |
| 免费包下载人数 | 核心价值是否成立 |
| 注册人数 | 用户是否愿意留下身份 |
| 测试反馈提交人数 | 用户是否真的行动 |
| 后续合作申请人数 | 商业路径是否成立 |
| 分成申请人数 | 低成本合作模式吸引力 |

### 8.2 质量指标

| 指标 | 意义 |
| --- | --- |
| 用户是否能说清产品是什么 | 定位是否清楚 |
| 用户是否信任网站 | 专业度是否足够 |
| 用户是否觉得剧本可制作 | 内容资产是否有效 |
| 用户是否愿意推荐给别人 | 价值感是否真实 |
| 用户是否愿意为后续内容付费或分成 | 商业模型是否成立 |

### 8.3 建议目标

第一轮测试不追求大数据。

建议目标：

- 邀请 10 个测试用户。
- 至少 6 个用户成功下载免费包。
- 至少 3 个用户愿意注册。
- 至少 2 个用户实际制作或明确表示愿意制作。
- 至少 1 个用户提交测试反馈。
- 至少 1 个用户对后续合作表达真实兴趣。

如果达到这个水平，说明项目值得继续打磨。

如果下载率很低，先优化剧本展示和信任感。

如果下载高但制作低，先优化免费包使用说明和制作门槛。

如果制作高但合作低，先优化后续合作价格、授权和交付方式。

## 9. 反馈收集问题

给用户的问题不要太多，建议分成两组。

### 9.1 下载后立即问

1. 你是否能快速理解这个网站是做什么的？
2. 哪一套剧本最吸引你？为什么？
3. 你愿不愿意下载前三集？如果不愿意，原因是什么？
4. 你觉得这个网站可信吗？哪里让你不信任？
5. 你觉得免费包应该包含哪些内容才值得你制作？

### 9.2 制作或试用后问

1. 这套前三集是否足够你做一次视频测试？
2. 剧本节奏、分镜、AI 提示词是否可用？
3. 你制作过程中最大的阻碍是什么？
4. 如果数据不错，你会更倾向买断、按集，还是分成？
5. 你能接受什么价格或分成比例？
6. 你是否愿意把收益数据回传给平台？如果不愿意，原因是什么？
7. 你还希望平台提供什么支持？

## 10. 本阶段不要急着做的事

本阶段不建议马上做：

- 大规模 UI 重设计。
- 大规模投流。
- 接正式支付。
- 完整文件上传系统。
- 自动分账系统。
- 大批量生成几十套剧本。
- 复杂会员体系。
- 过早设计品牌包装。

这些都应该等真实用户反馈回来后再做。

原因是现在最缺的不是功能数量，而是真实用户是否认可这个方向。

## 11. 当前 MVP 可以对外测试的边界

可以开放给测试用户体验：

- 首页。
- 剧本库。
- 剧本详情页。
- 免费前三集下载。
- 注册 / 登录。
- 用户中心。
- 测试反馈提交。
- 后续合作申请。
- 后台人工审核。
- 买断 / 按集 / 分成的完整演示流程。

需要提前说明：

- 当前仍是测试版本。
- 付款和分成合作以人工沟通为准。
- 分成合作需要线下或电子协议确认。
- 平台不保证播放量和收益。
- 用户使用免费包只能测试前三集，不代表获得完整版权。

## 12. 测试成功标准

### 可以继续推进的信号

出现以下情况，说明项目方向值得继续：

- 用户能快速理解“先免费测试，再决定后续合作”。
- 用户愿意下载前三集。
- 用户愿意拿剧本去制作视频。
- 用户主动问第 4 集以后怎么获取。
- 用户询问买断、按集或分成规则。
- 用户愿意提交测试数据。
- 用户愿意接受分成合作的基本规则。
- 用户指出的问题主要是体验和信任优化，而不是否定需求本身。

### 需要暂停重构的信号

出现以下情况，需要重新审视方向：

- 多数用户不知道网站价值。
- 多数用户认为免费包没有制作价值。
- 用户下载后完全不愿制作。
- 用户认为剧本质量不适合短视频。
- 用户只想免费看，不愿提供反馈或后续合作。
- 用户强烈不信任分成模式。
- 用户愿意买剧本，但不接受当前授权和交付方式。

## 13. 第一轮测试执行建议

### 第 1 天：准备测试环境

- 确认网站可以公网访问。
- 确认下载、注册、登录、用户中心和后台流程可用。
- 准备 3-5 套可展示剧本。
- 准备一段测试邀请话术。
- 准备反馈收集表。

### 第 2-4 天：邀请第一批用户

- 先邀请 5 个用户。
- 不解释太多，让他们自然浏览。
- 记录他们第一反应。
- 观察他们是否完成下载。

### 第 5-10 天：追踪制作和反馈

- 询问是否已开始制作。
- 收集制作过程卡点。
- 引导提交测试反馈。
- 记录后续合作意向。

### 第 11-14 天：复盘

整理：

- 哪些页面用户看不懂。
- 哪些剧本最吸引人。
- 哪些用户下载但没有制作。
- 哪些用户愿意后续合作。
- 用户最担心的问题是什么。
- 下一轮应该优先优化什么。

## 14. 下一步建议

在正式邀请用户前，建议先完成两件事：

1. 写一份 `docs/mvp-test-feedback-form.md`
   用来整理测试用户要填写的问题，避免反馈散落在微信、聊天记录和口头表达里。

2. 做一次“测试用户视角”的完整走查
   从首页开始，不看代码，只模拟一个创作者第一次进入网站的真实体验，记录所有疑惑点。

当前项目已经可以进入用户验证阶段。

但这次验证的目标不是证明我们已经成功，而是尽快发现真实用户到底是否愿意使用、愿意测试、愿意继续合作。

如果用户愿意走完前三集验证路径，这个项目就有继续做下去的商业基础。
