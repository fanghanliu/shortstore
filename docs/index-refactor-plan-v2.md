# 首页改造计划 V2

## 1. 文档目标

本文档用于规划 `index.html` 的实际改造，但本阶段不修改代码。

改造目标是把当前“AI短剧故事板购买页”升级为“免费前三集验证 + 验证后续作”的新商业模型首页。

本计划衔接以下文档：

- `business-model-v2.md`
- `free-three-episodes-package.md`
- `licensing-and-revenue-share.md`
- `product-page-copy-v2.md`
- `free-preview-lie-scent-v1.md`

## 2. 当前页面问题

当前首页主要表达仍然是旧模型：

- 首屏主张是“买一套AI短剧故事板”。
- CTA 是“获取完整包”。
- 剧本卡片按钮仍然是“购买”。
- 价格区是 A档 / S档 / S+档。
- 表单字段是“购买版本”。
- 页面没有明确说明“前三集免费验证”。
- 页面没有解释“买断 / 按集 / 分成”三种后续路径。
- 授权边界没有在领取前被用户看见。

这些表达会让用户继续把产品理解成一次性素材包，而不是先验证再转化的内容资产模型。

## 3. 改造原则

### 先改用户决策路径

页面第一目标不是卖完整包，而是让用户领取前三集并开始测试。

首页应引导用户完成：

1. 看懂剧本。
2. 领取前三集。
3. 制作发布。
4. 看数据。
5. 选择买断、按集或分成。

### 保留现有视觉资产

当前页面已有故事板图、卡片流、关键帧展示和抽屉交互。第一版改造应优先复用这些结构，减少重做成本。

可保留：

- 顶部导航结构。
- Hero 左文案右视觉结构。
- 故事板卡片流。
- 关键帧展示区。
- 剧本资产库区。
- 预览弹窗。
- 右侧抽屉表单。

需要重写：

- 首屏文案。
- CTA 文案。
- 卡片状态和按钮。
- 价格区内容。
- 表单字段。
- 弹窗文案。
- 授权说明。

### 不把分成做成无门槛按钮

分成合作需要审核账号、制作能力和数据回传意愿。页面可以展示“申请分成合作”，但不能表现成用户点击后自动获得授权。

### 免费不等于无限授权

所有“免费领取前三集”的附近，都要出现简短边界说明：

```text
免费包仅授权前三集测试使用。第4集及以后内容需选择买断、按集付费或版权分成。
```

## 14. app.js 改造范围

当前 `app.js` 功能简单，第一版改造建议只做最小改动。

### 必改

- `submitLead` 的按钮文字恢复值。
- 如果表单字段从一个 select 变成两个 select，不需要额外 JS 也能工作。

### 可选

- 点击不同剧本卡片的“领取前三集”时，自动把抽屉中的“选择剧本”设置为对应剧本。
- 点击续作方式按钮时，在用途说明中预填“咨询买断 / 购买后续剧集 / 申请分成合作”。
- 给按钮增加 `data-intent`，区分免费领取、买断、按集、分成。

### 不建议第一版做

- 自动下载 Markdown 免费包。
- 接入真实支付。
- 接入表单提交后端。
- 做复杂状态管理。

目标：补齐免费包内容、验证流程和授权边界。

## 19. 验收标准

改造完成后，页面应满足：

- 首屏能在3秒内让用户理解“前三集免费验证”。
- 页面不再把低价体验版作为入口。
- 用户能明确知道免费包包含什么。
- 用户能明确知道第4集以后需要续作方式。
- 买断、按集、分成是并列路径，不是价格高低三档。
- 授权边界在提交前可见。
- 抽屉表单是“领取申请”，不是“购买意向”。
- 移动端没有明显文字溢出或按钮拥挤。
- 预览弹窗和抽屉仍能正常打开关闭。

## 20. 暂不处理事项

本次首页改造暂不处理：

- 真实下载免费包。
- 真实支付。
- 用户登录。
- 数据回传后台。
- 分成合作审核后台。
- 自动生成免费包。
- `actors.html` 的商业模型调整。

这些可以在首页完成 V2 表达后再逐步规划。
