# 订单文案与付款说明规范

## 1. 文档目标

本文档用于规范后台生成订单、填写付款说明、开放交付内容时的默认文案。

当前项目已经完成了以下链路：

```text
用户提交后续合作申请 -> 后台审核通过 -> 后台生成订单 -> 用户中心查看订单 -> 后台确认付款 -> 用户中心开放交付
```

这套链路目前仍是人工收款和人工确认付款的 MVP 阶段，所以文案必须让用户明确知道：

1. 这是一条待处理订单，不是自动支付订单。
2. 用户需要按照平台约定完成付款或沟通确认。
3. 后台确认付款后，后续剧本内容才会开放。
4. 交付内容、授权范围和付款金额必须写清楚，避免误解。

本文档不是正式合同模板，只用于产品页面、后台填写和用户中心展示的业务文案标准。涉及买断、独占授权、版权分成、长期合作时，仍建议补充正式协议。

## 2. 涉及字段

当前系统中，订单和交付相关文案主要落在以下字段：

| 位置 | 字段 | 用途 |
| --- | --- | --- |
| 订单 | `Order.title` | 用户中心和后台看到的订单标题 |
| 订单 | `Order.orderType` | 合作类型：买断、按集购买、版权分成 |
| 订单 | `Order.amountCents` | 订单金额，单位为分 |
| 订单 | `Order.paymentNote` | 付款说明或付款确认备注 |
| 订单 | `Order.userVisibleNote` | 用户可见的订单处理说明 |
| 交付 | `Delivery.title` | 用户中心看到的交付标题 |
| 交付 | `Delivery.note` | 用户可见的交付说明 |
| 交付资源 | `DeliveryAsset.title` | 单个交付文件名称 |
| 交付资源 | `DeliveryAsset.filePath` | 交付文件路径或外部链接 |

后台填写文案时，应优先保证 `Order.title`、`Order.paymentNote`、`Order.userVisibleNote`、`Delivery.title`、`Delivery.note` 这五个字段清晰完整。

## 3. 基本文案原则

### 3.1 写清楚用户买的是什么

订单标题和说明必须包含：

- 剧本名称
- 合作方式
- 交付范围
- 是否包含商用授权
- 是否需要付款后开放

不要只写：

```text
后续合作订单
```

应该写：

```text
《她闻到谎言》第4-10集按集购买订单
```

### 3.2 不承诺未完成能力

当前系统还没有接入在线支付、发票、合同签署和自动通知，所以文案中不要出现：

- 立即在线支付
- 自动到账
- 系统自动发货
- 已签署正式合同
- 平台担保结算

建议使用：

- 请按平台约定完成付款
- 付款确认后开放交付内容
- 后台确认付款后可在用户中心查看交付
- 正式授权范围以双方确认的订单和补充协议为准

### 3.3 区分订单状态和交付状态

订单状态表示钱款和交易进度，交付状态表示内容是否开放。两者不要混用。

| 状态 | 用户理解 |
| --- | --- |
| `pending_payment` | 订单已生成，等待付款确认 |
| `paid` | 付款已确认，交付内容已开放或准备开放 |
| `delivered` | 订单对应内容已交付 |
| `cancelled` | 订单已取消，不再继续处理 |

付款前，交付可以提前创建，但应保持锁定，不在用户中心展示。付款确认后，交付内容才对用户开放。

## 4. 订单标题规范

### 4.1 一次性买断

适用于用户希望一次性获取整套剧本后续内容。

标题格式：

```text
《剧本名》完整买断订单
```

如果不是独占买断，应避免使用“独家”“唯一”“全版权”等容易误解的词。

示例：

```text
《她闻到谎言》完整买断订单
```

如果是独占买断，必须在标题和说明中明确独占范围：

```text
《她闻到谎言》短视频平台独占买断订单
```

### 4.2 按集购买

适用于用户只购买部分后续剧集，边测试边追加。

标题格式：

```text
《剧本名》第X-Y集按集购买订单
```

示例：

```text
《她闻到谎言》第4-10集按集购买订单
```

如果只购买单集：

```text
《她闻到谎言》第4集按集购买订单
```

### 4.3 版权分成

适用于用户不预付剧本费用，后续按收益比例分成。

标题格式：

```text
《剧本名》版权分成合作确认单
```

示例：

```text
《她闻到谎言》版权分成合作确认单
```

分成合作通常不应填写高额订单金额。若当前 MVP 必须生成订单，可将金额设置为 0，并在付款说明中写清楚“无需预付，按后续收益结算”。

## 5. 用户可见订单说明模板

`Order.userVisibleNote` 用于告诉用户当前订单为什么生成、接下来该做什么。

### 5.1 待付款通用模板

```text
你的后续合作申请已通过。当前订单用于确认本次合作范围和付款金额，请按平台约定完成付款。付款确认后，后续剧本内容会在用户中心的“我的交付”中开放。
```

### 5.2 买断订单模板

```text
你的买断申请已通过。本订单对应《剧本名》的完整后续内容交付，包含双方确认范围内的剧集正文、分镜和 AI 提示词。请按平台约定完成付款，付款确认后交付内容将在用户中心开放。
```

### 5.3 按集购买订单模板

```text
你的按集购买申请已通过。本订单对应《剧本名》第X-Y集内容。请按平台约定完成付款，付款确认后，对应剧集的正文、分镜和 AI 提示词将在用户中心开放。后续如需继续购买，可再次提交合作申请。
```

### 5.4 分成合作确认模板

```text
你的版权分成合作申请已通过。本合作无需预付剧本费用，后续将按照双方确认的收益口径和分成比例结算。请先确认合作范围、分成比例、结算周期和数据回传方式，确认后平台将开放后续制作内容。
```

## 6. 付款说明模板

`Order.paymentNote` 在待付款阶段应写“用户怎么付款或怎么确认”。在付款确认后，可以改写为“后台确认了什么”。

### 6.1 待付款说明

```text
请通过平台约定方式完成付款，并在付款后联系平台确认。后台确认付款后，交付内容会自动开放到你的用户中心。
```

如果有线下收款账户，可以写成：

```text
请按照客服提供的收款方式完成付款。付款备注建议填写你的注册邮箱和剧本名称，便于后台核对。后台确认付款后，交付内容会开放到用户中心。
```

不要在没有正式配置前，把个人收款账号硬编码进页面或默认模板。收款信息建议由人工客服或后台配置提供。

### 6.2 付款确认备注

后台将订单状态改为 `paid` 时，建议填写：

```text
付款已确认，交付内容已开放领取。
```

如果需要记录内部核对信息，可以写在 `adminNote`，不要把流水号、手机号、完整账户信息暴露给用户。

用户可见版本建议：

```text
付款已确认。请前往用户中心的“我的交付”查看后续剧本内容和使用说明。
```

### 6.3 订单取消说明

后台将订单状态改为 `cancelled` 时，建议填写：

```text
本订单已取消，如需继续合作，请重新提交后续合作申请或联系平台确认新的合作方案。
```

如果因为超时未付款取消：

```text
由于订单长时间未完成付款确认，本次订单已取消。如仍需继续购买后续内容，请重新提交合作申请。
```

## 7. 交付说明模板

`Delivery.title` 和 `Delivery.note` 用于用户付款后领取内容。

### 7.1 买断交付

交付标题：

```text
《剧本名》完整买断交付包
```

交付说明：

```text
本交付包包含《剧本名》双方确认范围内的完整后续内容。请优先阅读使用说明和授权边界，再进行视频制作、发布和团队分发。未经额外约定，不得转售原始剧本文件、分镜文件或提示词资源包。
```

建议交付资源：

| 文件标题 | 文件内容 |
| --- | --- |
| 完整剧本正文 | 全部后续剧集正文 |
| 分镜与制作说明 | 分镜、镜头节奏、制作注意事项 |
| AI 提示词包 | 中英双语画面提示词 |
| 授权与使用说明 | 商用范围、禁止行为、售后边界 |

### 7.2 按集购买交付

交付标题：

```text
《剧本名》第X-Y集交付包
```

交付说明：

```text
本交付包仅包含《剧本名》第X-Y集内容，授权范围仅覆盖本次购买剧集。请勿擅自续写、转售或分发未购买的后续内容。如本批次测试效果良好，可在用户中心继续提交后续合作申请。
```

建议交付资源：

| 文件标题 | 文件内容 |
| --- | --- |
| 第X-Y集剧本正文 | 本次购买剧集正文 |
| 第X-Y集分镜 | 对应剧集分镜和制作节奏 |
| 第X-Y集 AI 提示词 | 中英双语画面提示词 |
| 使用说明 | 授权范围和注意事项 |

### 7.3 分成合作交付

交付标题：

```text
《剧本名》分成合作交付包
```

交付说明：

```text
本交付包用于版权分成合作场景。用户可按照双方确认范围制作后续内容，并需按约定周期回传播放、收益和账号数据。收益口径、分成比例、结算周期和退出机制应以双方确认的合作说明或正式协议为准。
```

建议交付资源：

| 文件标题 | 文件内容 |
| --- | --- |
| 合作剧集内容 | 已开放的后续剧集正文 |
| 制作与发布说明 | 更新节奏、平台建议、风险提示 |
| 数据回传模板 | 播放、收益、涨粉、评论等数据填写方式 |
| 分成合作说明 | 收益口径、分成比例、结算周期 |

## 8. 后台填写流程建议

### 8.1 审核通过合作申请

后台处理合作申请时，建议按以下顺序填写：

1. 确认合作类型：买断、按集购买、版权分成。
2. 填写用户可见审核说明。
3. 如涉及付款，生成待付款订单。
4. 如内容已准备好，可同时创建交付记录，但交付状态保持待付款锁定。
5. 付款确认后，将订单状态改为已付款。
6. 系统开放对应交付内容。

### 8.2 生成订单时必填信息

生成订单时，后台至少应确认：

- 剧本名称
- 合作类型
- 交付范围
- 金额
- 付款说明
- 用户可见说明

如果这六项中有任何一项不清楚，订单不应生成。

### 8.3 创建交付时必填信息

创建交付时，后台至少应确认：

- 交付标题
- 交付说明
- 至少一个交付资源
- 资源名称
- 资源路径或下载链接
- 该资源是否与本订单范围一致

交付资源不要放无关内部文件，也不要把管理员备注、用户联系方式、付款凭证放进交付包。

## 10. 后续代码落地建议

下一步可以把本文档中的模板写入后台订单生成流程，减少管理员手动输入成本。

建议优先级：

1. 后台通过合作申请时，根据合作类型自动生成订单标题。
2. 后台通过合作申请时，自动填入默认 `userVisibleNote`。
3. 后台生成订单时，自动填入默认 `paymentNote`。
4. 后台创建交付时，自动生成交付标题和交付说明。
5. 对买断、按集购买、分成合作分别提供可编辑模板。
6. 后续再加入“付款凭证上传”“在线支付”“合同签署”“站内通知”。

## 11. 验收清单

订单文案进入代码前，至少应满足：

- 用户能看懂自己买的是哪套剧本。
- 用户能看懂本次订单覆盖哪些剧集或合作范围。
- 用户能看懂当前是否需要付款。
- 用户能看懂付款后去哪里领取内容。
- 后台能区分用户可见说明和内部备注。
- 分成合作不会被误解为一次性买断。
- 按集购买不会被误解为整套剧本授权。
- 买断合作不会默认承诺独占版权。
- 交付说明中包含使用边界和禁止转售提醒。
