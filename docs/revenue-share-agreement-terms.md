# 版权分成协议核心条款清单

## 1. 文档目标

本文档用于整理版权分成合作协议中必须明确的核心条款。

它不是最终合同文本，而是给三类对象使用的基础清单：

1. 业务侧：知道和用户谈版权分成时必须谈清楚什么。
2. 产品侧：知道后台表单、数据库字段、用户中心页面需要记录什么。
3. 法务侧：后续可以基于这些条款起草正式协议。

版权分成合作不能只依赖网页确认按钮。系统可以记录流程、数据、证据和结算状态，但授权边界、收益口径、违约责任和争议解决必须通过协议约束。

参考法律底座：

- 《中华人民共和国著作权法》关于作品许可使用合同的规定。
- 《中华人民共和国民法典》合同编关于合同效力、履行、违约责任等规则。

官方参考链接：

- https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html
- https://www.npc.gov.cn/c2/c30834/202009/t20200927_307879.html

## 2. 协议定位

版权分成协议建议定义为：

```text
剧本作品非独占许可使用 + 视频制作发布授权 + 收益分成结算协议
```

它不是：

- 剧本版权转让协议。
- 完整买断协议。
- 独占授权协议。
- 劳务外包协议。
- 用户免费获取剧本的凭证。

如果确实要提供独占使用、完整买断或项目联营，应另行签署更严格的协议。

## 3. 合作主体条款

协议必须明确双方主体。

### 3.1 平台方信息

建议记录：

- 主体名称
- 统一社会信用代码或身份证明
- 联系人
- 联系电话
- 邮箱
- 收款账户
- 通讯地址

如果当前还没有公司主体，也必须明确个人主体身份，并在正式商业化前考虑主体合规。

### 3.2 用户方信息

建议记录：

- 用户姓名或公司名称
- 身份证号或统一社会信用代码
- 联系电话
- 邮箱
- 微信
- 常用联系地址
- 收益结算账户
- 账号运营主体

如果用户是团队或 MCN，应确认签约主体是否有权代表实际运营账号。

### 3.3 后台字段建议

```text
project.partyAName
project.partyAContact
project.partyBName
project.partyBIdentity
project.partyBContact
project.partyBSettlementAccount
```

## 4. 授权作品条款

协议必须明确本次授权的是哪一套剧本。

建议记录：

- 剧本名称
- 剧本 slug 或内部编号
- 剧本版本
- 剧本集数
- 免费前三集是否已经授权测试
- 本次分成合作从第几集开始
- 是否包含分镜
- 是否包含 AI 提示词
- 是否包含角色设定、标题建议、封面建议

示例：

```text
本协议授权作品为《她闻到谎言》短剧剧本，授权版本为 v1，授权内容从第4集起按批次开放。
```

### 后台字段建议

```text
project.scriptId
project.scriptVersion
project.authorizedEpisodeStart
project.authorizedEpisodeEnd
project.includesStoryboard
project.includesPrompts
```

## 5. 授权性质条款

必须写清楚授权性质，避免用户误以为获得完整版权。

建议默认：

```text
非独占、不可转让、不可再授权、限约定账号和平台使用的制作发布许可。
```

### 5.1 是否独占

默认不独占。

如果用户要求独占，应另行约定：

- 独占平台
- 独占地区
- 独占账号
- 独占期限
- 独占价格或保底收益
- 平台是否停止向其他用户开放同剧本

### 5.2 是否允许转授权

默认不允许。

用户不得把剧本文件、提示词、分镜或后续内容授权给其他账号、团队、MCN 或客户使用。

### 5.3 是否允许改编

建议允许轻微制作改编，但不允许改变核心设定后绕开分成。

可约定：

- 可以调整台词、镜头、节奏、标题、封面。
- 不得改变核心人物关系、核心设定、主线结构后声称不是同一作品。
- 不得将剧本改成其他付费项目、课程、素材包或客户项目。

### 后台字段建议

```text
project.licenseType = non_exclusive
project.transferable = false
project.sublicensable = false
project.adaptationScope
project.exclusivityScope
```

## 6. 授权平台与账号条款

版权分成必须绑定发布平台和账号。

### 6.1 授权平台

建议记录：

- 抖音
- 快手
- 视频号
- 小红书
- TikTok
- YouTube Shorts
- 其他平台

默认规则：

```text
未在协议中登记的平台，不得发布后续分成内容。
```

### 6.2 授权账号

建议记录：

- 平台名称
- 账号昵称
- 账号 ID
- 账号主页链接
- 账号主体
- 是否允许矩阵号

默认规则：

```text
未登记账号不得使用本剧本后续内容。
```

如果允许矩阵账号，应列明每个账号，不能笼统写“旗下所有账号”。

### 后台字段建议

```text
project.authorizedPlatforms
project.authorizedAccounts
project.allowAccountMatrix
project.accountOwner
```

## 7. 交付方式条款

版权分成默认应分批交付。

### 7.1 默认分批交付

建议写入：

```text
平台根据用户制作、发布、数据回传和结算情况，分批开放后续剧集。
```

推荐批次：

```text
第1批：第4-10集
第2批：第11-20集
第3批：第21-30集
后续批次根据数据和结算情况继续开放
```

### 7.2 下一批开放条件

建议约定：

- 上一批视频已按约定发布。
- 用户已提交全部视频链接。
- 用户已提交收益数据和截图证明。
- 平台已审核通过。
- 上一周期分成已结算。
- 未发生违规使用或泄露剧本。

### 7.3 暂停交付

平台在以下情况下可暂停：

- 用户停更。
- 用户未回传数据。
- 用户未结算分成。
- 用户使用未登记账号。
- 用户疑似虚报收益。
- 用户泄露或转卖剧本。

### 后台字段建议

```text
batch.episodeStart
batch.episodeEnd
batch.status
batch.releaseCondition
batch.releasedAt
batch.lockedReason
```

## 8. 收益口径条款

这是协议最重要的部分之一。

### 8.1 有效收益定义

建议定义为：

```text
用户因使用授权剧本制作、发布、运营相关视频内容而直接或间接获得的可归因收益。
```

### 8.2 默认纳入收益

建议纳入：

- 平台广告收益。
- 创作者激励收益。
- 短剧播放收益。
- 付费解锁收益。
- 因该剧本视频产生的商业合作收益。
- 因该剧本视频产生的带货或转化收益，若双方约定纳入。

### 8.3 默认排除收益

可排除：

- 用户账号其他非本剧本视频收益。
- 用户历史视频收益。
- 与本剧本无关的直播打赏。
- 与本剧本无关的带货佣金。
- 与本剧本无关的商业合作。

### 8.4 必须单独约定的收益

以下收益必须单独写清：

- 带货佣金是否纳入。
- 直播引流收益是否纳入。
- 私域转化收益是否纳入。
- 课程、社群、素材包收益是否纳入。
- 多平台搬运收益是否纳入。
- 付费短剧小程序收益是否纳入。

### 后台字段建议

```text
project.revenueDefinition
project.includeAdRevenue
project.includeCreatorIncentive
project.includePaidUnlockRevenue
project.includeCommerceRevenue
project.excludedRevenueScope
```

## 9. 分成比例条款

协议必须明确分成比例和计算方式。

示例：

```text
用户确认的有效收益中，平台方享有 30%，用户方享有 70%。
```

### 9.1 固定比例

适合 MVP：

```text
平台 30%，用户 70%
```

### 9.2 阶梯比例

适合成熟合作：

```text
月收益 0-10,000 元：平台 30%
月收益 10,001-50,000 元：平台 25%
月收益 50,001 元以上：平台 20%
```

### 9.3 保底分成

可约定：

- 用户支付保底授权费。
- 保底费用是否抵扣平台分成。
- 保底费用是否可退。
- 未达到收益时如何处理。

### 后台字段建议

```text
project.shareRatioPlatform
project.shareRatioUser
project.minimumGuaranteeCents
project.guaranteeDeductible
project.shareRuleType
```

## 10. 成本扣除条款

如果要在分成前扣除成本，必须写清楚。

可能涉及：

- 平台手续费
- 投流费用
- 剪辑费用
- 配音费用
- 素材费用
- 账号运营费用
- 税费

建议 MVP 阶段先不要做复杂成本扣除，除非用户能提供清晰凭证。

推荐写法：

```text
除双方另有书面确认外，本协议按用户实际收到或平台后台显示的有效收益总额进行分成，不默认扣除用户自行支出的制作、投流或运营成本。
```

### 后台字段建议

```text
project.allowCostDeduction
statement.deductibleCostCents
statement.costEvidenceFiles
```

## 11. 数据提交条款

用户必须按周期提交数据。

### 11.1 提交周期

建议：

```text
用户应在每月 1-5 日提交上月数据。
```

### 11.2 提交内容

每期至少包括：

- 视频链接清单
- 对应剧集
- 发布平台
- 发布账号
- 发布时间
- 播放量
- 点赞量
- 评论量
- 收益金额
- 收益截图
- 平台后台截图
- 提现或结算截图

### 11.3 逾期处理

可约定：

- 逾期提醒。
- 逾期暂停下一批交付。
- 连续逾期视为违约。
- 平台有权终止授权。

### 后台字段建议

```text
statement.periodStart
statement.periodEnd
statement.submittedAt
statement.status
video.videoUrl
video.episodeNumber
video.revenueCents
evidence.filePath
```

## 12. 审核与对账条款

平台应保留审核权。

建议写入：

```text
平台方有权对用户提交的视频链接、后台截图、收益数据和结算记录进行审核。如数据存在异常，平台方有权要求用户补充证明材料。
```

### 12.1 审核方式

可包括：

- 人工审核链接。
- 对比公开视频播放量。
- 核对收益截图。
- 要求录屏证明。
- 要求临时共享后台数据。
- 要求授权只读数据权限。

### 12.2 争议处理

如双方对收益有争议：

- 先要求用户补充证明。
- 平台暂缓下一批交付。
- 双方确认争议金额。
- 必要时按协议争议解决条款处理。

### 后台字段建议

```text
statement.reviewedBy
statement.reviewedAt
statement.confirmedRevenueCents
statement.disputeReason
statement.auditNote
```

## 13. 结算与支付条款

### 13.1 结算周期

建议月结：

```text
每自然月为一个结算周期。
```

### 13.2 结算时间

示例：

```text
用户每月 1-5 日提交上月数据；平台每月 6-10 日审核；双方确认后，用户应在每月 15 日前支付平台分成。
```

### 13.3 支付方式

建议记录：

- 支付账户
- 支付方式
- 支付备注
- 是否需要发票
- 税费承担

### 13.4 逾期支付

可约定：

- 逾期提醒。
- 暂停下一批交付。
- 逾期违约金。
- 终止授权。
- 追偿费用承担。

### 后台字段建议

```text
statement.platformShareCents
statement.userShareCents
statement.paymentDueDate
statement.paidAt
statement.paymentProofPath
```

## 14. 用户义务条款

用户至少应承诺：

- 只在授权平台和账号发布。
- 不转卖、泄露、共享剧本文件。
- 不擅自转授权第三方。
- 按约定频率制作和发布视频。
- 按周期提交真实数据。
- 按时支付平台分成。
- 接受平台合理审核。
- 不虚报、漏报、隐瞒收益。
- 不把剧本改造成其他项目绕开分成。

## 15. 平台义务条款

平台至少应承诺：

- 按约定批次交付剧本内容。
- 提供已约定的剧本、分镜、提示词或说明文件。
- 对用户提交数据进行合理审核。
- 按约定确认结算金额。
- 不无故暂停已满足条件的交付。
- 对用户商业数据和账号信息保密。

## 16. 保密条款

保密范围建议包括：

- 剧本文本
- 分镜
- AI 提示词
- 角色设定
- 交付文件
- 未公开剧情
- 收益数据
- 账号后台截图
- 双方沟通记录
- 合作价格和分成比例

保密义务应在协议终止后继续有效。

### 后台字段建议

```text
project.confidentialityAcceptedAt
project.confidentialityScope
```

## 17. 知识产权归属条款

建议明确：

- 原始剧本著作权归平台方或原权利人所有。
- 用户仅获得协议范围内的使用许可。
- 用户制作的视频成片可归用户或双方按约定享有。
- 原始剧本、角色设定、世界观、分镜、提示词不因用户制作视频而转让。
- 用户不得申请与剧本相关的商标、版权登记或同名商业项目，除非另有书面授权。

这是防止用户误以为“拍了视频就拥有剧本版权”的关键条款。

## 18. 违约责任条款

### 18.1 典型违约行为

用户违约包括：

- 未按期提交数据。
- 未按期支付分成。
- 虚报、漏报、隐瞒收益。
- 使用未授权账号发布。
- 擅自转授权。
- 泄露或转卖剧本文件。
- 把剧本用于未约定项目。
- 拒绝配合审核。

平台违约包括：

- 无故不交付约定批次内容。
- 无故拒绝审核或确认结算。
- 泄露用户账号数据和收益数据。

### 18.2 违约后果

可约定：

- 暂停交付。
- 终止授权。
- 要求删除未授权内容。
- 要求补交分成。
- 支付违约金。
- 赔偿实际损失。
- 承担维权费用。

### 后台字段建议

```text
project.riskStatus
project.pausedReason
project.terminatedAt
project.terminationReason
project.breachRecords
```

## 19. 协议期限和终止条款

### 19.1 协议期限

建议明确：

- 起始日期
- 结束日期
- 是否自动续约
- 续约条件

### 19.2 终止条件

可包括：

- 合作期满。
- 双方协商一致。
- 用户连续停更。
- 用户逾期结算。
- 用户泄露剧本。
- 用户虚报收益。
- 平台无法继续授权。

### 19.3 终止后的处理

必须明确：

- 已发布视频是否可以保留。
- 未发布内容是否停止使用。
- 未结算收益如何处理。
- 用户是否删除本地剧本文件。
- 已开放但未制作内容是否收回授权。

## 20. 通知和沟通条款

协议应约定有效通知方式：

- 邮箱
- 微信
- 手机短信
- 平台站内通知
- 后台系统通知

建议写入：

```text
用户在平台填写的邮箱、手机号、微信或站内账号为有效通知渠道。
```

### 后台字段建议

```text
project.noticeEmail
project.noticeWechat
project.noticePhone
project.lastNoticeAt
```

## 21. 争议解决条款

正式协议必须明确：

- 适用法律
- 管辖法院或仲裁机构
- 争议处理流程
- 维权费用承担

MVP 文档阶段不直接固定具体法院或仲裁机构，应由法务根据主体所在地和交易结构确定。

## 22. 用户确认清单

签署或确认协议前，用户应逐项确认：

- 我知道本合作不是买断。
- 我没有获得完整剧本版权。
- 我不得转卖、泄露或转授权剧本文件。
- 我只能在约定平台和账号使用。
- 我需要按月提交视频链接和收益证明。
- 我需要按约定比例支付平台分成。
- 我未按期提交数据或支付分成时，平台可以暂停交付。
- 我虚报、漏报收益或违规使用时，需要承担违约责任。

这部分后续可以做成用户中心的确认复选框。

## 23. 后台创建分成项目时必填字段

当后台通过版权分成申请时，至少应填写：

- 合作用户
- 合作剧本
- 授权平台
- 授权账号
- 分成比例
- 结算周期
- 第一批交付集数
- 数据提交周期
- 合同文件或协议确认记录
- 收益口径
- 违约暂停规则

如果这些信息缺失，不应直接开放分成项目。

## 24. 与现有系统的关系

当前系统中的版权分成申请，后续应从：

```text
0元订单 + 交付包
```

升级为：

```text
分成项目 + 分批交付 + 视频回传 + 月度结算
```

订单仍可保留，但只用于：

- 保底费用。
- 保证金。
- 已确认结算金额。
- 补款或违约金。

版权分成的主对象应该是 `RevenueShareProject`，不是 `Order`。
