# 测试环境部署说明 v1

## 目标

把当前网站先部署成一个可公开访问的测试站，让外部用户可以点击、浏览、下载免费前三集验证包，并把体验问题反馈回来。

当前阶段先采用静态部署，不接入后端和数据库。这样可以最快拿到公网测试链接，同时不会影响后续正式架构重置。

## 已整理的测试部署目录

部署目录：

```text
deploy-test-site/
```

目录中只包含测试站需要公开访问的文件：

- `index.html`：首页。
- `scripts.html`：剧本库页面。
- `script-lie-scent.html`：《她闻到谎言》详情页。
- `actors.html`：AI 演员页面。
- `styles.css`：页面样式。
- `app.js`、`script-detail.js`、`actors.js`：前端交互脚本。
- `assets/`：图片和分镜素材。
- `downloads/free-preview-lie-scent-v1.md`：免费前三集验证包下载文件。
- `*.json`：当前首页卡片所需的本地剧本数据。

## 推荐部署方式

### 方式一：Netlify Drop

适合最快测试。

1. 打开 `https://app.netlify.com/drop`。
2. 登录或注册 Netlify。
3. 将 `deploy-test-site/` 文件夹拖到页面中。
4. 等待上传完成。
5. 复制 Netlify 生成的公开链接，发给测试用户。

注意：如果平台不接受文件夹拖拽，可以先使用 `deploy-test-site.zip`，解压后再上传解压出来的文件夹。

### 方式二：Cloudflare Pages Direct Upload

适合之后继续沿用为测试环境。

1. 进入 Cloudflare Dashboard。
2. 创建 Pages 项目。
3. 选择 Direct Upload。
4. 上传 `deploy-test-site/` 文件夹。
5. 生成测试访问链接。

### 方式三：Vercel

适合未来接入前端框架或服务端能力后继续使用。

当前版本是纯静态站，可以上传静态文件或后续接 Git 仓库部署。这个阶段不作为首选，是因为 Netlify Drop 和 Cloudflare Direct Upload 对静态测试更快。

## 上传后必须测试的路径

拿到公开链接后，至少检查这些页面：

```text
/
/index.html
/scripts.html
/script-lie-scent.html
/actors.html
```

重点点击测试：

- 首页顶部「进入剧本库」是否跳到剧本库。
- 首页主按钮是否跳到剧本库。
- 剧本库中《她闻到谎言》是否能进入详情页。
- 详情页「免费下载前三集验证包」是否弹出授权确认弹窗。
- 勾选确认后，下载按钮是否可点击。
- 下载文件是否为 `free-preview-lie-scent-v1.md`。
- 手机端打开时，首页、剧本库、详情页是否有明显错位。

## 测试反馈收集建议

给测试用户的问题不要太多，先围绕是否愿意继续使用来问：

- 你是否能在 30 秒内理解这个网站卖什么？
- 你是否信任这个网站提供的免费前三集下载？
- 你最想先点哪个剧本？
- 剧本详情页是否足够专业？
- 免费包下载流程是否顺畅？
- 哪个位置让你觉得像广告、像低质站、或不够可信？
- 如果你是短视频创作者，你会不会愿意拿前三集去测试？

## 当前版本边界

当前测试环境不包含：

- 登录注册。
- 数据库。
- 后台管理。
- 在线支付。
- 自动授权合同。
- 用户下载记录。
- 剧本详情页动态路由。

这些能力会放到后续正式架构阶段处理。当前测试站只验证：用户能否理解产品、找到剧本、进入详情页、下载免费验证包。

## 下一步建议

测试链接发出去后，优先收集 5-10 个真实用户反馈。反馈回来后再决定下一轮改造重点：

- 如果用户不信任，优先优化品牌可信度、下载说明、授权说明。
- 如果用户找不到剧本，优先优化剧本库列表和分类筛选。
- 如果用户不愿下载，优先优化详情页预览内容和免费包价值表达。
- 如果用户愿意下载但后续无法转化，再进入买断、按集、分成的购买流程设计。
